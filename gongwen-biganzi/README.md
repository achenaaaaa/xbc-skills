## 📖 项目简介

"公文笔杆子"是李继刚在 2024 年底发布的经典 Claude System Prompt，用 **Lisp 伪代码 DSL** 精确控制 LLM 行为，将任意用户输入转化为严谨、规范、善用典故的公文典范，并以 **SVG 卡片** 形式精美排版输出。

这是中文 AI 圈公认的 Prompt Engineering 教科书级作品。

---

## 🎯 核心能力

| 能力 | 说明 |
|------|------|
| **万物转公文** | 任意输入 → 正式公文格式，语言严谨、用词规范 |
| **角色精准** | 15年公文经验 + 名校中文系 + 公务员考试一次过 |
| **Few-shot 内置** | 完整会议通知范例，含格式、措辞、落款 |
| **SVG 卡片输出** | 860×1220 极简主义排版，京华老宋体，视觉优雅 |
| **最小指令控制** | `start()` 启动 → `公文写作` 主逻辑 → `生成卡片` 渲染 |

## 🔬 设计分析

### 为什么这个 Prompt 是"神作"？

#### 1. Lisp 伪代码 DSL — 极简压缩
```lisp
(defun 笔杆子 ()
  "公文写作专家, 被誉为部门笔杆子"
  (list (经历 . "名校中文系毕业...")
        (技能 . "精通公文写作规范...")
        (表达 . "语言严谨, 用词规范, 善用典故警句")))
```
- 点对（`.`）结构向 LLM 传递"属性-值"的精确语义
- `list` 包装传递"这是一个整体角色"的语义
- 相比 Markdown 模板式 Prompt，Lisp 风格更精准、更不易被 LLM "漂移"

#### 2. 函数式管道 — 精确控制数据流
```lisp
(-> 用户输入
    场景特点
    合理扩展
    尊重事实
    要点清晰
    正面教育意义)
```
- `->` 管道操作符让 LLM 理解这是一个 **顺序处理流程**
- 每一步都是精炼的关键词，不给 LLM 自由发挥的冗余空间

#### 3. Few-shot 内嵌 — 直接给模板
- 完整会议通知：标题 → 正文 → 会议时间/地点/议程 → 落款 → 日期
- 这种格式让 LLM 直接"照猫画虎"，质量一致性极高

#### 4. SVG 输出控制 — 超越纯文本
- 860×1220 画布，移动端适配
- 极简主义 + 四原则（对齐、重复、对比、亲密性）
- `KingHwa_OldSong` 字体传递"官方/正式/传统"感

#### 5. 运行规则 — 防止偏差
```
1. 初次启动时必须*只运行 (start) 函数*
2. 接收用户输入之后, 调用主函数 (公文写作 用户输入)
3. 严格按照(生成卡片) 进行排版输出
4. 输出完 SVG 后, 不再输出任何额外文本解释
```
- 用 `*只运行*` 和 `严格` 等强调词对抗 LLM 的"多说两句"倾向

## ⚖️ 优缺点评价

### ✅ 优点

1. **Prompt 设计艺术的天花板** — Lisp DSL + 函数式管道 + 点对结构，极简且精准
2. **角色设定教科书** — 3 条属性（经历/技能/表达）说透一个角色，不冗余
3. **Few-shot 质量标杆** — 内置示例给出了完整格式模板
4. **输出格式创新** — SVG 卡片比纯文本更有仪式感和传播力
5. **跨领域可迁移** — 这套 Lisp DSL 方法论可复用到任何专业领域
6. **社区影响力大** — 被无数 Prompt Engineer 逐行拆解学习

### ❌ 缺点

1. **非正式公文标准** — 不遵循 GB/T 9704-2012，不适合党政机关正式场景
2. **偏创意公文** — 善用"典故警句"，更像"笔杆子"个人风格而非标准化公文
3. **仅适配 Claude** — `(require 'dash)` 和函数嵌套对 GPT 系列效果不确定
4. **无交互工作流** — 一次性输出 SVG，不支持多轮修改、审阅、格式调整
5. **Few-shot 质量不稳定** — 只有一个示例，复杂文种（如报告、请示）可能偏离
6. **SVG 依赖 Claude 渲染能力** — 输出质量高度依赖 Claude 的 SVG 生成质量
7. **缺少 15 种法定公文类型支持** — 不区分通知/报告/请示/批复等文种的格式差异

## 💡 改进方向建议

1. **增加文种识别** — 根据用户输入自动判断通知/报告/请示/函等文种
2. **补充 GB/T 9704 支持** — 红头、发文字号、红线分割等格式元素
3. **多轮交互** — 支持"生成→审阅→修改→定稿"工作流
4. **Few-shot 扩增** — 每种公文类型至少 1 个完整范例
5. **脱敏处理** — 自动替换用户输入中的敏感信息
6. **输出多格式** — 除 SVG 外，支持 DOCX/PDF 导出
7. **参数化** — 支持用户指定文种、密级、紧急程度等参数
